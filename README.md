# jasongen

jasongen generates Go code from OpenAPI 3 specs (Swagger 2.0 specs are converted automatically). Clients are small and readable: every operation is a context-first method with typed parameters and models, you bring your own http.Client for transport and auth, and retries/backoff are opt-in. On the server side it generates a chi router, a service interface for you to implement, and logging and Prometheus metrics middleware for that service. It can also generate a JavaScript client from the same spec.

## Configuration

Generator settings that don't belong in the spec can be put in a YAML config file and passed to `jasongen template` with `--config`. This keeps them out of the spec, so they also work for specs you can't (or don't want to) edit, such as third-party specs or ones generated by a framework.

```yaml
# jasongen.yaml
initialisms:
  - IPAM
  - VLAN
```

```bash
jasongen template --config jasongen.yaml mypkg client client.go openapi.yaml
```

Unknown keys are an error, so a typo fails generation instead of being silently ignored.

### Initialisms

Go identifiers are built from the names in the spec (schema names, property names, operation IDs, parameters). Words that are initialisms are kept fully upper case, so `user_id` becomes `UserID` rather than `UserId`.

jasongen starts with [snaker's common initialisms](https://github.com/kenshaw/snaker/blob/master/snaker.go) (`API`, `HTTP`, `ID`, `IP`, `URL`, `UUID`, ...). Anything listed under `initialisms` in the config file is added to that set:

| Spec name     | Without config | With `IPAM` and `VLAN` |
|---------------|----------------|------------------------|
| `ipam_prefix` | `IpamPrefix`   | `IPAMPrefix`           |
| `vlan_id`     | `VlanID`       | `VLANID`               |

Entries are case-insensitive and must be at least two letters or digits.

Adding or removing an initialism renames every generated identifier that contains it, which is a breaking change for code using the generated package. Pick the list before publishing a client, and keep the config file next to the spec so every generation uses the same one.
